# @namzu/desktop

## 0.2.2

### Patch Changes

- a79a18c: The free Zen models load again. Zen moved its catalogue endpoints to per-wire paths, so every launch's refresh failed and the model list stayed on the copy saved before the move, missing the models Zen offers now. The CLI bundled with the app reads the new paths (`@namzu/zen` 5.0.0), and the list refreshes on launch. A conversation set to a model Zen retired, such as `cat-jam-free`, needs a current one picked from the model list.

## 0.2.1

### Patch Changes

- f1ca711: Mark the unfinished rail destinations as in progress and make the menu bar read like an app, not a browser.

  Spaces, Scheduled and Plugins in the left icon rail are now shown in progress: each is disabled, carries an "— in progress" tooltip, and no longer opens, because that work has not started yet. They return when it lands. The rail's "More" (⋯) overflow menu is removed — both of its actions already exist elsewhere: **Add new project** is in the sidebar and the title bar, and the sidebar toggles from the title bar's panel control or Ctrl/Cmd+B.

  The native **View** menu no longer offers Reload, Force Reload or Toggle Developer Tools; it keeps zoom and full screen. The developer tools remain in a development build only.

- f86a456: A Pal's conversation now uses the Pal's current model. Before, the model the Pal had when its conversation opened was kept for good, so changing the Pal's model afterwards (or setting it after the page filled in a default) never reached the conversation. Nothing to change on your side; a model picked by hand in the Pal's composer is still kept for that conversation.

## 0.2.0

### Minor Changes

- 1fa60b9: You can now connect a provider from inside the app. When nothing can answer yet, the composer says "Add an API key or sign in to start" with one button that opens Settings ▸ Models, instead of letting your first message fail. Models lists each provider and how it is connected (a key in your environment, a key you saved, an existing Claude or ChatGPT sign-in, a local server, the free tier), lets you paste a key, check it and remove it. The key is saved by the Namzu command line in its own private file and is never kept in the window.

  Failures now read in plain words with a next step: a rejected key opens Settings, a provider outage says your message is saved, a rate limit shows "Waiting for Anthropic to accept more requests… retrying in 6s" instead of a silent Working, a stopped reply that cannot be repeated offers a new conversation, and the provider's own message sits behind Details. A folder deleted while open says it can't be found and offers Locate folder or Remove project; a crashed connection keeps your conversation on screen, reconnects once by itself and clears its own error; an engine that cannot start is named and its button no longer shows an empty bar. Approval cards say what they would replace.

- 9ae74be: Namzu Desktop is now an installed Windows app that keeps itself up to date. Download the installer once, run it (no administrator prompt; Windows may show an "unknown publisher" warning because the installer is not signed yet, so choose More info, then Run anyway), and your conversations, drafts and settings carry over from the development app. From then on Namzu checks for a new version in the background, downloads it, and only restarts when you choose Restart, never while a reply, a permission request or a terminal is in use. Settings ▸ Updates shows "Up to date" or "Update available" and lets you turn automatic downloads off.

  Since 0.1.0 you also get: real terminal tabs for the Namzu CLI, Codex and Claude Code beside your conversations (open from the composer or the + menu, with the composer's text sent as the first message); updates for Codex, Claude Code and the Namzu command line from Settings ▸ Updates, run in a visible terminal tab and only when you click; a compact sidebar with one surface per row and a tab-strip menu for new conversations, terminals and windows; faster engine start-up (Codex starts once instead of per chat); local Turkish speech bundled with its own Python; and many smaller fixes to terminals, focus and settings wording.

  If you installed Namzu Desktop before this version, that copy cannot update itself: install this version once by hand and later versions arrive on their own.

- 5071556: The Windows installer can carry the light Pal computer image. `scripts/stage-installer.mjs` takes `--pal-computer-image <archive>` (and `--pal-computer-manifest <file>`, which defaults to `manifest.json` beside the archive), checks the manifest against the archive (name, size, SHA-256) and stages both under `extra/pal-computer`, which `electron-builder.yml` installs as `resources/pal-computer`. The archive is already compressed and is stored as built. The manifest's `imageRef` must be `namzu-local-computer:<revision>` (a test tag is refused). The release workflow does not pass the flag yet, so installers built by CI carry only the `README.txt` until the pipeline supplies the image. Nothing loads the image at run time yet; a build staged without the flag installs a `README.txt` there instead.
- cea5487: On Windows, Pal computers now run on Windows' own Linux container support and Namzu Desktop sets the PC up from the Pal computer row. Nothing changes for you if you already set `NAMZU_PAL_COMPUTER_ENGINE`; off Windows nothing changes at all. The row shows "Needs setup", then one sentence about what Windows will add and ask, then one progress label at a time; a restart is offered as "Restart now" and setup continues by itself after you sign in again. The Linux machine stops after 10 idle minutes.
- 78b24dc: The sidebar, tab strip, terminals and command palette are easier to read and drive. There is one **Add new project** button, on the Projects heading; a project row no longer has a one-click ×, and its **…** menu holds Open folder, Archived conversations and Remove project…; each conversation is listed once (Recents shows only what a project's list is not showing, with the project's name); an **Archived conversations** entry in the sidebar lists every project; Archive has no ellipsis and its Undo stays 20 seconds. Two terminals of one project are named `sh · app` and `sh 2 · app`, and a terminal's dot says what it means on hover. The front tab always scrolls into view and a **Show all tabs** menu lists the rest; a caret beside **+** and the terminal tab menu open the split entries, which close the docked sidebar to make room instead of scrolling the page sideways. New keys: Ctrl+W (⌘+W) closes a tab, Ctrl+Tab, Ctrl+Shift+Tab and Ctrl+1 to 9 switch, Ctrl+Shift+PageUp and PageDown reorder, Ctrl+Shift+backslash opens a terminal to the right, and Ctrl+, works from a terminal (inside a terminal Ctrl+W still belongs to the shell; Ctrl+F4 closes the tab). Terminal find and the multi-line paste confirmation are announced in the pane. Search ignores Turkish I, ı, İ and i differences and no longer breaks under a Turkish system language. The palette says "conversations", lists recent ones, Archived, tab and split actions, and shows a chord as one keycap. A conversation reopens at the scroll position you left it, and a finished Codex, Claude Code or Namzu update closes its own terminal tab.
- b6ea5ca: Models work on first open with nothing to set up. With nothing saved, Namzu Desktop and the terminal app now start on what they find, in this order: a sign-in Namzu already reuses (Claude Code, Codex), an API key in the environment, a local server (Ollama on port 11434, LM Studio on port 1234; each probe waits at most 300 ms and they run together), then the keyless Zen free models. They say what they picked in plain words ("Using your Claude sign-in, found on this computer.") and save nothing, so a key or sign-in added later wins on the next open. `/model` and the model picker change it.

  What changes for you: in the terminal app a first run with an API key or a local server in the environment no longer stops at the provider picker; it starts on that provider. The picker still opens when nothing is available. In Desktop the keyless Zen free models now count as usable, as they already did in the terminal app, so a new person's message box is ready and Send works at once; the "Add an API key or sign in to start" card now appears only when nothing at all is available. To keep the old terminal behaviour of choosing yourself, save a choice once with `/model`.

  When Zen declines a free request that carried no key, both apps now say "Zen didn’t accept the free model right now. Try again in a while, or choose another provider. A Zen API key also works." and keep the technical detail under Details (Desktop) or `--debug` (terminal). The generic `provider.permission` explanation in `@namzu/sdk` no longer says the key authenticated: a 403 only says the request was refused.

- 6943add: The Desktop can now start a Pal for a message waiting in its inbox, on the person's click. After an approved `send_pal_message` to a Pal that is not running, the sender's transcript asks "Start _name_ now?" and the Pal's own page offers the same (or **Resume** for a paused Pal). **Start** runs the same finite dispatch as `namzu pal dispatch` in the Pal's own host, in the background: the sender's turn is never held, the Pal reads the message in its own conversation under its own permission rules, and its approvals stay in its own tab. A Pal that is already running is only reported, repeated clicks start once, and a missing Pal computer is explained in plain words with **Retry** instead of starting.

  The CLI's desktop host gains two methods, `namzu/pals/inbox/status` and `namzu/pals/inbox/start`; an older runtime simply shows no question. Nothing about sending changes: a message still only reaches the inbox, and `send_pal_message` still never starts a Pal itself. If you embed the CLI's authorization, an owner-conversation wake now also accepts a click-evidence object (`operatorWake: { evidence }`) besides `true`; with neither, a wake is still refused.

  New and optional: `ToolResult.facts`, a closed union (`ToolFacts`) of a command's exit code and its stdout and stderr as head-and-tail windows (`ToolTextWindow`) or a note that the output was binary, a read's path and size, a search's and a listing's counts, whether a write created, updated or left a file, and the kind of a failure (`ToolFailureReason`). The built-in `bash`, `read`, `grep`, `glob`, `edit` and `write` tools set it, `tool_completed` and the ACP `tool_call` update carry it, a generic `ToolCallView` may carry `facts` for what the call is about, and `admitToolFacts` reads a saved one back. A call refused without running, an unknown tool and a thrown filesystem error also carry a `failure` fact. `execHostShell` additionally returns `stdoutBytes` and `stderrBytes`. A post-tool hook that replaces the output also drops `facts`, so a redaction is never undone.

  If you build a view of tool output yourself, read these fields instead of the `STDOUT:` and `STDERR:` labels, the "Found 2 match(es)" and "1 replacement(s)" sentences and the notes about withheld credentials or shortened output, which are the model's interface and are not stable text to parse.

  The Desktop app now words every tool row from those fields (Read a.ts, Searched for export, Ran npm test · failed (exit 3), Couldn't read missing.txt: file not found), draws a command's colours, folds long output to its first and last lines with Show more, says "Binary output, 3 KB" instead of printing the bytes, counts a finished edit in the reply's changes card, shows paths in approvals relative to the project, and leaves "0s" off work that took under a second. The CLI host restores a saved conversation's `facts` (without a command's output) so a reopened row reads the same.
