# @namzu/desktop

## 0.2.0

### Minor Changes

- 1fa60b9: You can now connect a provider from inside the app. When nothing can answer yet, the composer says "Add an API key or sign in to start" with one button that opens Settings ▸ Models, instead of letting your first message fail. Models lists each provider and how it is connected (a key in your environment, a key you saved, an existing Claude or ChatGPT sign-in, a local server, the free tier), lets you paste a key, check it and remove it. The key is saved by the Namzu command line in its own private file and is never kept in the window.

  Failures now read in plain words with a next step: a rejected key opens Settings, a provider outage says your message is saved, a rate limit shows "Waiting for Anthropic to accept more requests… retrying in 6s" instead of a silent Working, a stopped reply that cannot be repeated offers a new conversation, and the provider's own message sits behind Details. A folder deleted while open says it can't be found and offers Locate folder or Remove project; a crashed connection keeps your conversation on screen, reconnects once by itself and clears its own error; an engine that cannot start is named and its button no longer shows an empty bar. Approval cards say what they would replace.

- 9ae74be: Namzu Desktop is now an installed Windows app that keeps itself up to date. Download the installer once, run it (no administrator prompt; Windows may show an "unknown publisher" warning because the installer is not signed yet, so choose More info, then Run anyway), and your conversations, drafts and settings carry over from the development app. From then on Namzu checks for a new version in the background, downloads it, and only restarts when you choose Restart, never while a reply, a permission request or a terminal is in use. Settings ▸ Updates shows "Up to date" or "Update available" and lets you turn automatic downloads off.

  Since 0.1.0 you also get: real terminal tabs for the Namzu CLI, Codex and Claude Code beside your conversations (open from the composer or the + menu, with the composer's text sent as the first message); updates for Codex, Claude Code and the Namzu command line from Settings ▸ Updates, run in a visible terminal tab and only when you click; a compact sidebar with one surface per row and a tab-strip menu for new conversations, terminals and windows; faster engine start-up (Codex starts once instead of per chat); local Turkish speech bundled with its own Python; and many smaller fixes to terminals, focus and settings wording.

  If you installed Namzu Desktop before this version, that copy cannot update itself: install this version once by hand and later versions arrive on their own.

- 78b24dc: The sidebar, tab strip, terminals and command palette are easier to read and drive. There is one **Add new project** button, on the Projects heading; a project row no longer has a one-click ×, and its **…** menu holds Open folder, Archived conversations and Remove project…; each conversation is listed once (Recents shows only what a project's list is not showing, with the project's name); an **Archived conversations** entry in the sidebar lists every project; Archive has no ellipsis and its Undo stays 20 seconds. Two terminals of one project are named `sh · app` and `sh 2 · app`, and a terminal's dot says what it means on hover. The front tab always scrolls into view and a **Show all tabs** menu lists the rest; a caret beside **+** and the terminal tab menu open the split entries, which close the docked sidebar to make room instead of scrolling the page sideways. New keys: Ctrl+W (⌘+W) closes a tab, Ctrl+Tab, Ctrl+Shift+Tab and Ctrl+1 to 9 switch, Ctrl+Shift+PageUp and PageDown reorder, Ctrl+Shift+backslash opens a terminal to the right, and Ctrl+, works from a terminal (inside a terminal Ctrl+W still belongs to the shell; Ctrl+F4 closes the tab). Terminal find and the multi-line paste confirmation are announced in the pane. Search ignores Turkish I, ı, İ and i differences and no longer breaks under a Turkish system language. The palette says "conversations", lists recent ones, Archived, tab and split actions, and shows a chord as one keycap. A conversation reopens at the scroll position you left it, and a finished Codex, Claude Code or Namzu update closes its own terminal tab.
- 6943add: The Desktop can now start a Pal for a message waiting in its inbox, on the person's click. After an approved `send_pal_message` to a Pal that is not running, the sender's transcript asks "Start _name_ now?" and the Pal's own page offers the same (or **Resume** for a paused Pal). **Start** runs the same finite dispatch as `namzu pal dispatch` in the Pal's own host, in the background: the sender's turn is never held, the Pal reads the message in its own conversation under its own permission rules, and its approvals stay in its own tab. A Pal that is already running is only reported, repeated clicks start once, and a missing Pal computer is explained in plain words with **Retry** instead of starting.

  The CLI's desktop host gains two methods, `namzu/pals/inbox/status` and `namzu/pals/inbox/start`; an older runtime simply shows no question. Nothing about sending changes: a message still only reaches the inbox, and `send_pal_message` still never starts a Pal itself. If you embed the CLI's authorization, an owner-conversation wake now also accepts a click-evidence object (`operatorWake: { evidence }`) besides `true`; with neither, a wake is still refused.

### Patch Changes

- 0888f71: The model popup keeps one width across its steps and engines, and the engine chip names its engine. An approval card sits above the composer with "Waiting for your decision" directly above it, a declined note appears as your own message, and Stop looks the same while a decision is awaited. After a reload, a message with an attached file shows the file as a chip, not the text sent to the model. A write that would change nothing says "No change to <file>."
- 86616b4: A reply that stops on a provider error such as a 502 is no longer a dead end. Without a token limit (the Desktop default) Try again sends it as a new request in the same conversation. If the conversation cannot repeat it, Continue without this reply closes the stopped reply and puts your message and its files back in the message box, not sent; if even that fails, Copy to a new conversation carries them to a new one. Details names the provider's answer once ("502 Bad Gateway") and says how many requests have unknown usage, with no receipt wording.

  Also: Send is visibly disabled with "Connect a provider to send" when nothing is connected, and Send or Enter lead to the Connect a provider card; the Zen row says "Free models. Needs a free Zen key." with Add key and Get a free key (Namzu counts a provider only once a key is saved); the engine error notice sits below the tab strip instead of over it.

- 45a0531: Setting up Codex or Claude Code from the model popup no longer ends in a dead end. An engine that is not installed shows **How to install** with the exact command for your system, a Copy button and **Check again** (also in Settings ▸ Updates); an engine that is installed but signed out says to sign in first, shows the command to run, and has an **Open terminal** button; the model button says "Not available" instead of staying a grey bar. The popup keeps one width across its steps, the effort slider shows its level names, one line explains Desktop | CLI, and the "Choose a model" heading is no longer covered by the engine mark.
- 1fa683f: Installed builds now check for updates: before this, an installer built from this repo shipped without an update feed and never checked.
- 8fdac46: A project whose folder is gone now appears in the composer's project chooser marked "Folder not found" and cannot be chosen. A message you send to a Pal also shows in that Pal's own conversation, quoted, with where it stands ("Waiting for the Pal to read it"), and the Pal's row in the sidebar shows a dot until you open it; nothing here starts the Pal. Delete Pal has an Open folder button that shows the Pal's folder. The Stop button's tooltip says why Queue is off. The File menu has Close tab, Next tab and Previous tab, and Ctrl+W now closes a terminal tab as well (Ctrl+C, Ctrl+D and the other keys stay the program's). Message times read "Sent at ..." for your messages and "Received at ..." for replies everywhere.
- a58aec0: The model popup header no longer draws the engine chip over the title. When the back link, title, engine chip, Desktop | CLI switch and search button do not fit one line, the chip, switch and search button move to a line under the title, and a title that is still too long ends in an ellipsis.
- d521813: Add an end-to-end check that a Namzu terminal tab keeps its message box, corners
  and model name intact as the window narrows and the tab is split. No change for
  people using the app.
- d08e7b7: Creating a Pal no longer makes two when you press Save twice, and the app no longer looks frozen while the new Pal starts. Save lets go as soon as the Pal is created; "Opening name…" (with Cancel, and Retry if the start fails) shows on the Pals page while it starts, and Customize, New Pal and Pause stay usable. A name that matches an existing Pal (any case, the Turkish dotted and dotless i included) is refused with a suggestion such as "pamir 2".
- 2d2a6c3: Pals read more plainly and no longer offer what cannot work. The approval card for a message to a Pal says "You can start the Pal after sending, and it will read the message on its own computer" and keeps the terminal command under Details. There is one Start, named for the Pal ("Start Işık"), and it starts the computer when that is needed. When no Docker or Podman is ready, Start is switched off in the offer under the sent message and on the Pal's page, with the missing piece in one sentence and a "How to set up" disclosure. A failed start is hidden once you dismiss it or the Pal's computer changes, the sidebar dot says whether your message is waiting, being read or not delivered, and an offline computer says that chatting works without it. Deleting a Pal names its folder ("Işık's files stay in its folder"), with the path only as a tooltip and behind Copy path. A duplicate name shows only the refusal. A new Pal starts from a model a connected provider actually lists, preferring the composer's current choice. The sidebar's "Opening…" goes as soon as the Pal is on screen.
- eb73a8e: Large runtime messages such as images no longer slow the window, because a message is joined once when its line ends instead of searched on every chunk.
- eea6a1a: Settings sections share one header, so the search box no longer jumps between pages. Updates stops claiming a "Last checked" time on a copy that cannot update itself, has one "Check for updates" button, shows an engine that reported it has no signed-in account as "Signed out - sign in to it in a terminal" (with Open terminal) instead of suggesting you are offline, and says whether the update server or the program itself did not answer. About lists the command line bundled with the app and one installed separately, and says which data folders are safe to delete. A narrow window's Changes panel has a "Back to conversation" button, and the first screen shows quiet placeholders instead of "Loading..." beside an empty-list hint.
- e613d10: Settings and a few screens read more plainly. Updates found together share one notice instead of stacking; Update from Settings keeps you in Settings with progress on the row and a link to the terminal output; the Updates page no longer offers an automatic-download switch where the app cannot update itself; a separately installed Namzu command line is labelled as such. The "waiting to restart" dialog says what it waits for. Speech before the download is one Download voice button, and About shows versions and your system in plain words with a Copy details button; raw folder paths appear only under Data folders. Settings search finds Turkish capitals (İ, ı), each page has one heading, and the terminal shell row appears only where there is a choice. On a narrow window the Changes panel takes the whole pane instead of squeezing the chat, the project chips sit flat on the composer's edges, and times follow your system's clock style everywhere.
- b98713e: The sidebar no longer puts a "Pals" heading above one to three Pals: the Pal rows and "Create your first Pal" sit directly under New conversation again, and only a fourth Pal makes a foldable "Pals" group (its folded state is remembered and only applies while the group exists). Recents is a plain heading again and no longer folds; a "recents" value saved by an earlier build is ignored. Projects still folds.
- 6329ab6: On a sidebar row, the close, pin and archive glyph shown on hover now sits exactly where the status dot it replaces sits, and the title's letters are centred with them. Before, the glyph was 6px nearer the middle of the row than the dot, and on Windows the title's letters sat almost 2px below the row's middle, so the glyph looked high next to them.
- dc4ae4d: The Pals, Projects and Recents headings in the sidebar now fold and unfold at any count, not only when there are more than three Pals. Folding hides the list without closing tabs or changing the open conversation, a small dot on a folded heading says when a Pal has a new message or a conversation is waiting, and the choice is remembered after a restart.
- 5a7ee46: Sidebar, tabs, projects and the folder-trust dialog read more plainly. A project's menu has "Rename project…", which changes the name Namzu shows and never the folder; a project whose folder is empty offers starters that fit it; a conversation without a project shows an "Add new project" row; a notice on a page with no composer no longer covers that page's button; a tab whose folder is missing keeps its conversation title and Pals offers Retry when its list cannot be read. Tabs keep whole words and hide a tab the strip would cut, an ended terminal is dimmed and closes on Enter or restarts on R, the hover card says where the conversation runs and never covers "Archived conversations", and the trust dialog says in words when a folder's settings turn off the sandbox.
- 6f93df9: Staging an installer without a cached Python archive no longer fails at its last step. Before this fix it downloaded Python, copied it, deleted the download, and then failed trying to measure the deleted file. The release workflow stages that way.
