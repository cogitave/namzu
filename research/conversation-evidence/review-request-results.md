# Reviewing the source actually attached to a candidate request

Recorded 2026-09-13 on base `f49a4b83`.
[Machine-readable controls, live receipt and build hashes](review-request-results.json).

## Defect and boundary

The [referential recall trials](resolved-query-results.md) recovered the correct
historical identifiers, but one current-state answer changed ASCII `I` to
Turkish `İ`. The earlier [visible-evidence trial](visible-evidence-results.md)
also recorded an exact-copy failure. Source retrieval and answer fidelity are
separate requirements; fixing one does not prove the other.

The existing `reviewAnswer` and `structuredOutput.review` callbacks received
`runMgr.messages`, which intentionally excludes ephemeral `prepareStep.context`.
A host reviewer could reread a privately held known source address, but it could
not identify a newly recalled source from the candidate request through the
review context itself. The fix adds optional `requestMessages` to that context.
The built-in runtime captures a separate copy of the messages dispatched into
the provider chain, after request projection and on any image-recovery retry.
Prose, tool-mode structured and native structured reviewers receive the snapshot
for their own candidate. A correction or resumed model turn captures anew.

The [Pydantic output-validator documentation](https://pydantic.dev/docs/ai/core-concepts/output/#output-validators)
describes validators with dependencies and retry feedback. That supports the
host-owned validation/correction pattern; it does not demonstrate an identical
request-snapshot API or guarantee factual answers. Namzu's change preserves its
existing distinction between a valid rejection and a failing validator.
No extra judge-model call, language-specific identifier repair or default CLI
factual validator is introduced.

## Probe

```sh
node research/conversation-evidence/review-request-cli.mjs --history-only
node research/conversation-evidence/review-request-cli.mjs
node research/conversation-evidence/review-request-cli.mjs --live
```

The seed is a separate production CLI `run-stream` process with scripted model
decisions: a real read observes a 350-line manifest, its full text is retained,
and its summary/short preview does not disclose the random receipt. The parent
then replaces the workspace file. A fresh process uses the built CLI's
`probeAgentSession` and `createAgentSession`, loading the same recorded
conversation with automatic evidence recall enabled and query resolution off.
This is an embedded CLI Session probe, not a new CLI flag or a TUI visual test.

The first candidate in every control is deliberately corrupted from the actual
request's recalled receipt (`RECEIPT` → `RECEİPT`). This is fault injection,
not a naturally occurring live-model error. In the live arm only the correction
is generated by the live `codex/gpt-5.6-luna` model, effort `low`; its stream is
forwarded unchanged. The task-specific reviewer chooses the source reference
from its supplied messages, rereads it through production conversation evidence
access, refuses previews or a mismatched quote, and compares the candidate
exactly to the receipt in that authenticated quote. It receives no private
expected-code argument. Feedback describes the mismatch without copying the
expected identifier into the feedback itself.

The history-only control deliberately inspects canonical `messages` instead of
the new request snapshot on the same built implementation. It is an availability
ablation, not a replay of an older binary. Corrected controls use
`requestMessages`. Source text remains historical; quote containment does not
prove arbitrary claims or present workspace state. The reviewer may read only
a page containing the exact bounded excerpt; it does not claim to inspect the
entire original tool result or establish absence elsewhere.

Bounds: 25,000 run tokens, three iterations, one correction opportunity,
90-second cancellation and 120-second parent process timeout. Seed bounds are
separate (three iterations, 25,000-token admission, 30 seconds; zero model spend).
The current file remains unchanged throughout review. Built modules have matching
before/after hashes. Random synthetic receipts and temporary paths are recorded;
no user transcript or credential is included.

## Results

| Arm | Reviewer sees request source | Source revalidated | Outcome | Live model tokens |
| --- | --- | --- | --- | ---: |
| History-only (`K5Rsbo`) | No, despite source being in the provider request | Cannot choose reference | Verification error; no settled answer | 0 |
| Scripted correction (`ppQ1L9`) | Yes | Before each verdict | First rejected, exact second accepted | 0 |
| Live correction (`0levpi`) | Yes | Before each verdict | First rejected, exact live second accepted | 8,246 |

In all arms canonical history had no request-context source block. The new field
therefore supplies evidence the reviewer could not get by simply rereading its
old `messages` argument. The live correction used one provider request: 8,185
input and 61 output tokens, matching the owning run's 8,246-token budget receipt.
Zero tokens for the other model decisions means they were scripted. One live
correction is a mechanism check, not a measured production error rate.

SDK regressions cover the three settlement paths, changing references during
correction, nested mutation isolation, last image-recovery dispatch and fresh
capture after checkpoint resume. CLI Session tests verify request-only source
selection and refuse an archive whose recorded owner changes before validation.
Existing cancellation, malformed-verdict and correction-exhaustion tests remain
in force. No source-changing action is replayed to recover output.

## Remaining work

This exposes the correct input to host validation; it does not install a general
factual reviewer in ordinary Namzu chat. The next policy must distinguish copying
an exact source value from transformation, hypothetical examples and unrelated
text. Blindly normalizing Unicode, rejecting all new identifiers, or assuming
text containment proves semantic support would create new failures. The natural
copy error remains relevant evidence while that broader policy is designed.
