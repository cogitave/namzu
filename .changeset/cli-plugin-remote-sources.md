`namzu plugin marketplace add` now accepts a GitHub `owner/repo` (with `#ref` or `@ref`), an `https://` Git repository, `user@host:path`, and an `https://` address of a `marketplace.json`, with `--ref` and `--sparse`; it shows what you are adding (owner, plugin count, commit) and asks first (`--yes` to accept, exit 75 with no terminal and no flag). New `namzu plugin marketplace update [name]` refreshes the catalog and says what is new; a marketplace pinned at a commit does not move. `namzu plugin install` and `update` now download catalog entries whose source is a repository, a folder of one, or an https zip, with `sha` and `sha256` pins; `update` shows what changed in what runs and asks again when anything that runs changed. Git is the system `git` with no prompts, https and ssh only, no hooks and integrity checks on, stopped after 120 seconds (`NAMZU_PLUGIN_GIT_TIMEOUT_MS`); LFS files and submodules are counted and not downloaded. New config key `plugins.blockedMarketplaces` (your own file and the managed file only) makes `add`, `update` and every download from a marketplace exit 77. What changes for you: an address that used to exit 69 with "needs a download" now downloads after you say yes, and exit 69 now also means Git is missing or the host did not answer. Nothing existing breaks; nothing is fetched until you run one of these commands.
