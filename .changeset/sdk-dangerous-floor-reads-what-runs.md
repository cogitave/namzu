The dangerous-command floor (`denyDangerousPatterns: true`) no longer refuses `sudo`, `doas`, `pkexec`, `su -`, `ssh user@host`, `eval` of a dynamic string, or a `curl`/`wget` piped into a shell. Those now come back from the gate as `review`, which a mode that asks puts to the person (allow once) and which `bypass` and `auto` approve like any other review. They are not ask rules: `explicitReview` and `askRule` stay unset on the call. If your host relied on the gate to refuse them, set `denyDangerousPatterns: 'strict'` (or add the rule `{ type: 'deny_dangerous_patterns', strict: true }`), which keeps every one of the previous patterns a denial in every mode, matched on the raw text as before. A host with nobody to ask now sees those calls refused by its review policy rather than by the gate, with that policy's wording.

Still refused in every mode, now in every spelling and only when it is the command that runs: a recursive removal of the file system root, the home folder, a top-level directory, or a variable that may be empty followed by one (`rm -fr /`, `rm -rf ~`, `rm -rf "$DIR/usr"`); `mkfs`; `dd` writing to a device with `of=/dev/…`; a fork bomb; `chmod 777 /`. `rm -rf /tmp/build` and `rm -f /usr/local/.wtest` match nothing, where the old `rm -rf /` pattern refused the first.

The floor now reads the commands a line runs (through the shell lexer), not its text, so a word inside quotes, an `echo` argument, a heredoc body or a comment is no longer a match, while a real `sudo` after `;`, `&&`, `|`, in a subshell, in `$( )` or in a `bash -c` payload still is. The refusal says what was refused (`this command removes the file system root.`) and tells the model that nothing ran and not to retry it or a reworded form; the old fixed "rewording it will not help" sentence is gone. `describeRule` for `deny_dangerous_patterns` takes the call to describe it. `denyDangerousPatterns` now accepts `boolean | 'strict'` and the rule type gains an optional `strict`. The `bash` and `monitor` tools' own check now stops only the irreversible tier, so it never takes back a command the gate let through as a question, and a command line given without a tool definition or as a tool's whole serialized input is still read as raw text.

The floor also reads through `xargs` and `find -exec`, a variable head word and a substitution that prints a name. `find / -delete` and `shred`, `wipefs -a` and a redirection on a device are stops. `mkfs` on a regular file, `dd of=/dev/shm/…` and `/dev/pts/…` are no longer stops.
