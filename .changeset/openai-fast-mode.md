`speed: 'fast'` is now honoured, where it used to be ignored. The API-key driver sends `service_tier: "priority"` to the models in the new `OPENAI_FAST_TABLE` and refuses any other model, any base URL that is not `api.openai.com`, and `'ultrafast'`, before a request, with a `bad_request` `ProviderRequestError` whose `providerCode` is `fast_mode_unsupported`. The Codex subscription driver sends `priority` (or, for `'ultrafast'`, `ultrafast`) plus the routing header only for a model whose account listing offers that tier, and refuses it otherwise or before the listing has loaded; the listing now fills `ModelInfo.speedTiers` and `CodexProvider.speedTiersFor`. The served tier is read back into `TokenUsage.speed` (`priority` and `fast` are `'fast'`, `default` and `auto` are standard, `flex` and `scale` land in `serviceTier`, and no echo means the tier asked for). New exports: `resolveFastModeVerdict`, `OPENAI_FAST_TABLE`, `PLAN_MULTIPLIER`, `isFirstPartyOpenAIEndpoint`, `servedSpeed`. Nothing changes unless a caller sets `speed`; if you already pass `speed: 'fast'` to this driver, it now takes effect (and costs more) on a listed model and fails the call on any other, so drop `speed` where you want standard speed.
