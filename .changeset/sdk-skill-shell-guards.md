A shell command a skill runs while it loads now answers to the turn's permission mode, and a value that lands inside such a command is quoted for the shell.

Permission mode: the `skill` tool only reads, so the review policy never saw the commands it ran, and in plan or strict mode a skill whose `allowed-tools` covered `touch` still changed files. A nested call now gets the answer the same call gets when the model makes it directly. Under `plan` a call that can change something is refused even when a rule allows it; under `strict` a call is refused unless a rule allows it, and a skill's `allowed-tools` never counts as a rule. The executor reads the mode from the name of the turn's approval policy (`approvalPolicyName`, kept current when the policy is swapped), so a host that names its policy for the review mode it implements gets this with no change. A host whose policy name is `plan` or `strict` but does not mean those modes should rename it. New: `nestedCallModeRefusal(mode, { readOnly, allowedByRule })`, which returns the reason a nested call may not run, for a host that loads text outside a turn.

Values: `substituteEscaped` now quotes a value that lands inside a command, one word at a time (`git log $ARGUMENTS` with `-n 5` becomes `git log '-n' '5'`), and escapes it for the quote it sits in when the author quoted it, so `;`, `|`, `&`, `$(`, backticks, redirections, newlines and `#` in a value are literal. This covers the skill's folder (`${NAMZU_SKILL_DIR}`, `${CLAUDE_SKILL_DIR}`) too, so a folder named like a command is only text. A value with a backtick, or one that would land in a here-document, a `${...}` or an arithmetic expansion, refuses the load. Text outside commands is unchanged. `substituteEscaped` takes a third argument, `{ dialect }`, to say which shell reads the command; the default is the host's shell. A skill that relied on a value being pasted into a command as shell syntax (an argument holding `a | b`) now gets it as plain words; build the pipeline in the skill instead.
