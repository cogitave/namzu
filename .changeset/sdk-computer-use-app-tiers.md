`computer_use` now works in an application by its kind. In a browser window it only looks (screenshots, tree reads, scroll, `focus_window`): a click, drag, `ui_act`, `ui_do`, `type_text` or a `key` other than a page-moving key (`PAGE_DOWN`, `PAGE_UP`, `HOME`, `END`, arrows, `SPACE`) is refused with a message that points to the browser tool. In an editor or IDE (and, as before, a terminal) it clicks but does not type or press keys, and the refusal points to the shell or edit tools. A call that names no window reads the window list once to find its application. The browser, editor and terminal names are a best-effort match on the reported process name. Every other application is unchanged, and `deniedApps` is still checked first. If you drove a browser page through `computer_use` (for example `key CTRL+L` or typing into a page field), use the browser tool for that, or an application not in the browser list. The exported `appTier` is internal to the module and not re-exported from the package index. The tool description also asks the model to look at the screen before stating an app's state, never to click links with computer use, and to prefer a connected tool or a command line.
