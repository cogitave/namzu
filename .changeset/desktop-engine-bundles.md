Publisher side of the engine that Namzu Desktop will keep current by itself (nothing in the installed app changes yet). The installer's command line folder gains a `kernel.json` at its root (command line and engine versions, `desktopContract`, `dataEpoch`, platform and arch, written from what the staged command line answers); every other file in it is byte for byte as before, and the installer staging and the new kernel staging now run one shared function. New plain `.mjs` commands under `packages/desktop/scripts/kernel/` stage, pack (a deterministic `.tar.gz` plus `files.json`), assemble a manifest, sign it with Ed25519 (the key only from `NAMZU_KERNEL_SIGNING_KEY`), verify it with an independent reader, make a key pair, and run the whole release locally. `packages/desktop/kernel-keys.json` is the public key list, empty until a real key exists. `.github/workflows/kernel-release.yml` publishes to the rolling release `kernel-latest`: it builds only when the command line is newer than the current manifest and on the registry, signs in the `kernel-release` environment, and re-issues the manifest weekly. See `docs/cli/desktop-engine-bundles.md`.
