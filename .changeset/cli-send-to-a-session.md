You can now say something to a running session from another terminal: `namzu send <session> "<text>"` (or pipe the text in, or `--file`), and in `namzu watch` press `m`, type a line and press Enter. The session's own terminal takes it at its next request boundary (or starts a turn for it when idle) and the model is told the text arrived from another terminal of your account and is meant to be yours, that the kernel did not check who sent it, and that it is not an approval. It cannot answer an approval or a question, change the permission mode or run a command, and text starting with a slash is just text. The command says what happened and exits by it: delivered 0, accepted but not taken yet 10 (it stays queued in that terminal), refused 1, unreachable 69 (finished or gone), not found 66. Only a terminal of your account on this machine that has the conversation open reads messages; background and scheduled sessions do not. Nothing changes for existing commands, except that `namzu watch` in a terminal now shows "m to message it" where it showed "read-only" (a pipe or `--plain` is unchanged), and every terminal now records which conversation it has open in its live-session file. A session's agents are kept out of this channel by three layers: every process a session starts (a command the model runs, a hook, a tool server, a sandboxed command, a terminal the session opened) now carries `NAMZU_STARTED_BY_SESSION=1` in its environment and `namzu send` refuses when it sees it; a built-in rule in every session's permission gate, in every mode, refuses a model-started command line that runs `namzu send` however it is wrapped (`env`, `setsid`, `nohup`, `sh -c`, by path to the CLI entry); and the sender and the receiving terminal check process ancestry. What is left is a process of your account that hides both its ancestry and its environment and is started by a script the command-line layer never read; a message from another terminal is as trustworthy as the account boundary, not more. If you ran `namzu send` from a tool, a hook or a session's terminal tab, run it from your own terminal. The transcript labels the message "Message from another terminal of this account", and the person's words are shown in a reopened conversation and in `namzu watch`, not only the label.
