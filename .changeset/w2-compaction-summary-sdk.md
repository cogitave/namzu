A host can now have a compaction summary written by a model it names. `QueryParams` and `AgentConfig` take `compactionSummaryRoute`, and `compactNow`, `compactSession`, `compactRegion` and `compactSessionRange` take `summaryRoute`: a function that resolves `{ provider, model, providerId? }`, or nothing. When it resolves a route, that model reads the span being replaced (tool results cut to `modelSummaryToolResultChars`, default 1,500 characters; the whole transcript to `modelSummaryInputChars`, default 240,000, keeping the first request and the newest entries) and writes the summary, with the person's requests quoted, the current work and the next step. An automatic pass charges the call to the turn at the route's model and provider; a host-triggered pass returns it in `CompactionResult.usage`. Nothing changes for a host that does not pass a route. When the route resolves nothing, the call fails, times out or returns no summary, the summary is the extracted working state as before, with its verifier step where `llmVerification` applies; the verifier does not run on top of a model-written summary. New optional `CompactionConfig` keys: `modelSummary` (default true; false ignores the route), `modelSummaryMaxTokens` (4,096), `modelSummaryInputChars`, `modelSummaryToolResultChars`. New exported types: `CompactionSummaryRoute`, `CompactionSummaryRouter`.
