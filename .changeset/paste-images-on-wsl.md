---
"@namzu/cli": minor
---

Pasting an image into the composer now works under WSL. Namzu reads the Windows clipboard through `powershell.exe` (found on the `PATH`, or at its fixed place under the Windows drive mount), and an empty terminal paste, which Windows Terminal sends for an image-only clipboard, attaches the image too. A paste made only of paths to image files, such as a dragged file or a `C:\...` path, attaches the files. Reading the clipboard no longer freezes the composer, and Enter pressed during a read waits for it. On Windows the image key is now `alt+v` only (`ctrl+v` stays the terminal's text paste); macOS and Linux keep `ctrl+v` and `alt+v`, and WSL binds both. If you rebound `chat:imagePaste` your binding is untouched. If `powershell.exe` cannot start, you get a message about Windows interop instead of a missing-tool hint.

An image larger than 5 MiB (as base64) is refused when pasted, with a message to save a smaller copy and paste its path, instead of failing every later turn. A clipboard read that fails for any reason other than "no image" (for example PowerShell blocked by policy) now says it could not read the clipboard rather than reporting an empty one, and file names with accented or non-Latin letters survive an Explorer copy. Dragged `C:\...` paths also attach on native Windows.

Images are now brought inside the provider's limits instead of only refused: anything over 2000 pixels on a side or 3.75 MiB is scaled to fit inside 2000 by 2000, then recompressed (palette PNG, JPEG at quality 80 down to 20, last a 1000 pixel wide JPEG), and BMP and other formats become PNG. This uses `sharp`, which is now an optional dependency of `@namzu/cli`, so an install may fetch a native binary for your platform; if it is not installed the CLI still works, images inside the limits still attach, and larger ones are refused with a message that says resizing is unavailable. On Linux the clipboard is asked what it holds first and a BMP is read when no PNG is offered. When the paste key finds no image it pastes the clipboard's text (2 second limit, binary text ignored), so a terminal that hands the key to Namzu instead of pasting loses nothing. A pasted or dragged image path now follows the same read policy as the read tool: a path a permission rule denies or asks about, or one outside the working directory and the folders added with `/add-dir`, is refused with a message and stays in the draft as text, so to attach an image from elsewhere add its folder or copy it into the project. A chip pasted after text now has a space before it. `NAMZU_NO_CLIPBOARD=1` stops Namzu from starting any clipboard program.
