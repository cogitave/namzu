A fenced code block in a reply is now drawn in syntax colour when its language is one we know (TypeScript, JavaScript, Python, Rust, Go, shell, JSON, YAML, TOML, HTML, Markdown, C, C++, C#, Java, Ruby, PHP, SQL, Dockerfile, PowerShell and the rest of the common set, under the usual short names such as `ts`, `py`, `sh`, `yml`). Keywords, strings, numbers, comments, the names of functions and types, `true` and `null`, and the added and removed lines of a `diff` block each take a colour of your theme; every theme has code colours, the colour-blind ones tell added from removed by blue against orange and keep the kinds of syntax apart under red-green colour blindness, and the 16-colour ones use only the terminal's named colours. The characters, rows and wraps are the same as before and a selection or `/copy` takes the code alone. A block with no language, an unknown one or `text` is drawn as it was, in the one code colour, and so is every block under `NO_COLOR`, `FORCE_COLOR=0` or a terminal that is not a colour terminal. A reopened conversation and `namzu watch` colour code too. To go back to the old look, set `tui.syntaxHighlight: false` in your own config (or the Code colour row of `/config`); nothing else changes, and the default of no documented setting changed. The highlighter (highlight.js 11.11.1) is read only when a reply holds a block in a language, so start-up is unchanged; a block waits at most a second and a half for its grammar and is drawn plain if it does not come.
