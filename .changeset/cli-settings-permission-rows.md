`namzu config` and `/config` edit the permission rules, the permission self-checks and the browser site levels as typed values (`namzu config` is new in this release, so nothing that used it before changes). `namzu config get --json` describes them with the control kinds `permission-rules`, `permission-checks` and `sites`. `namzu config set permissions` changes only the tool rules: `defaultMode`, `disableBypassMode`, `disableAutoMode`, `outsideRoot` and `autoMode` have their own keys, a table that names one of them is refused, and `namzu config unset permissions` removes only the rules. The `allow`, `ask` and `deny` lists of `Tool(specifier)` strings are read and saved back as the per-tool table. Each of the three asks first when a change lets more run without a person, and names it (a rule that allows added or made more permissive, a deny or ask rule removed; a check removed or changed; a site that becomes `act` or stops being `deny`); a change that only restricts saves at once. A tool must be written as the engine names it, in lower case (`bash`, not `Bash`): the other spelling was saved before and never matched. The examples for `permissionChecks` and `browser.sites` now show values the loader accepts. Config files are read as before.
