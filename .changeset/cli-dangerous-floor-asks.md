`sudo`, `su -`, `ssh user@host`, `eval` and a download piped into a shell are no longer refused outright in every mode. In `default`, `plan` and `accept-edits` you are asked and can allow the command once; `--yolo` (bypass) and auto mode run it, as they run any other question. Commands that cannot be undone are still refused in every mode, and are now recognised in every spelling: removing `/`, your home folder or a top-level directory such as `/usr`, a path under a variable that may be empty, `mkfs`, `dd` to a device, a fork bomb, `chmod 777 /`. A word inside quotes, an `echo` argument or a comment (`echo "needs sudo"`) no longer counts, so a harmless check no longer stops the line. When a command is refused, the row says what it was (`Blocked: this command removes the file system root.`) and the model is told nothing ran and not to retry. Scheduled scripts keep refusing every one of these, since nobody can be asked. This changes a default: `--yolo` used to refuse `sudo` and the rest, and now runs them. To keep refusing a command, add a `deny` rule for it under `permissions` (for `bash`, the pattern `sudo *`); there is no setting yet that restores the whole old list.
