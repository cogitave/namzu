Hooks can take over making and removing worktrees. `worktree_create` (`WorktreeCreate`) fires before a worktree is made with `worktreeName`, `worktreeRoot` and `worktreeBaseRef`; a shell hook makes the folder and prints it as its last line (or answers `hookSpecificOutput.worktreePath`) and the host uses it instead of Git. `worktree_remove` (`WorktreeRemove`) fires with `worktreePath` and the hook does the removing. With hooks on `worktree_create`, a failure or a missing path fails the creation with the hook's own words and never falls back to Git. New exports: `HookedWorkspaceDriver` and `worktreeHookHost` (wrap any `WorkspaceBackendDriver` so the two events apply to it), `WorktreeHookError`, `worktreeHookVerdict`, and the types `WorkspaceBackendDriver`, `CreateWorkspaceParams`, `BranchWorkspaceParams`, `WorkspaceInspection`, `WorktreeHookHost`, `WorktreeHookContext`; `GitWorktreeBackendMeta.hookOwned` marks a folder a hook made (the Git driver never removes it). Both events are in `PluginHookEvent` and `SHELL_HOOK_EVENTS`; `PluginHookContext` gains `worktreeName`, `worktreeRoot`, `worktreeBaseRef`, `worktreePath` and `PluginHookNotes` gains `worktreePath`. Nothing is removed and no default changes: a host that registers `GitWorktreeDriver` as before behaves as before. If you switch on a union of event names with an exhaustive check, add the two new names.
