A plugin can ship hook entries (a command, an http address or a prompt), and a command started for one finds the plugin's own folder. Nothing existing changes and nothing has to be done to upgrade: a hook command in a config file that refers to a variable ending in `_PLUGIN_ROOT` or `_PLUGIN_DATA` keeps running exactly as it did.

For a host that embeds the kernel: `PluginLifecycleManagerConfig.hooksFor` is called when a plugin is enabled and returns the hooks the host read for it; they are registered under the plugin's id, so disabling, uninstalling or a failed enable removes them with the plugin's other hooks, and `listHooks()` marks them `shell: true` so a host can list them apart from the plugin's JavaScript hooks. The manifest gains `hookEntries`, an events object written inline (kept as written; the host reads it), and a path in the manifest's `hooks` that ends in `.json` is now a file of entries and is no longer imported as a module (`isHookEntriesPath`); `hooks` is still a list of paths. `parsePluginManifestText` also reads the two spellings the common hook contract uses, `"hooks": "<file>"` (one path) and `"hooks": { <events> }` (read as `hookEntries`); both used to be refused. `ShellHookOptions.plugin` (`{ root, dataDir }`) starts every command of those entries with `NAMZU_PLUGIN_ROOT` and `NAMZU_PLUGIN_DATA` and creates the data folder when a command first runs. A name ending in `_PLUGIN_ROOT` or `_PLUGIN_DATA` that the command refers to and nothing sets is exported with the folder, under that name, so the script the command starts reads it; a shell command expands it itself and an entry in the exec form (`args`) has the folder put into its command and arguments (`MOVED_FOLDER_ENDINGS`, `isPluginFolderVariable`, `PluginFolders`; `substitutePluginFolders` stays exported).

Smaller: the hook's shell is found on the host's own `PATH`, so an entry whose `env` sets `PATH` to something without `sh` still starts; the "refers to variables set nowhere" report skips loop and `read` variables and names a shell keeps for itself (new exports `assignedWithin` and `isShellOwnVariable`); in the exec form the project folder variable (`$X_PROJECT_DIR`) is put into the command and arguments as the plugin folders are.
