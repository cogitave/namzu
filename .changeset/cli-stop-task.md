One tool, `stop_task`, now ends the delegated work the model started: an agent task (by task id or name) or a workflow run (by the run id `agent_task_list` returns). A stopped run aborts its running agents, never starts its queued ones and keeps its journal, so a later `workflow` call with `resumeFromRunId` reuses what finished. Something that already ended answers "already ended". `stop_task` replaces `cancel_agent`, which leaves the model's tool list and the `cancel_agent` input name `task_id` becomes `id`; a permission rule, `--allowed-tools` or `--disallowed-tools` entry that names `cancel_agent` now applies to `stop_task`, and a resumed conversation whose history calls `cancel_agent` still loads. Shell jobs and monitors keep the `job` tool. `stop_task` is always loaded wherever `Agent` or `workflow` can be offered. The model is also told when to use it: background work it started is its to end when the person changed course, a result in hand answers the question or an earlier stage failed, not when it is only slow, and to say in one sentence what it stopped. The Agent description, the workflow launch receipt, the large-run notice and the hypermode reminders say so, and the Agent text now says a background agent is still running and prefers `send_message` to a finished agent over starting a new one. Only permission rules and tool flags map the old name: a hook matcher that names `cancel_agent` no longer matches and must name `stop_task` (`task_id` is now `id`). Nothing else to change.
