'@namzu/cli': minor
---

New launch options, on `namzu`, `namzu resume`, `namzu exec` and `namzu -p`: `--system-prompt <text|@file>` replaces Namzu's own system prompt text for the launch (tools, `--append-system-prompt`, project instructions and memory still apply); `--tools <list>` offers the model only the named tools (`""` none, `default` all), which removes tools rather than setting a permission rule; `-n, --name <name>` names the conversation; `--bare` starts without hooks, plugins, project instruction files, saved memory notes, learning, the code index, the background model catalogue refresh and the update check; `--debug-file <path>` writes every log record, debug level included, to a file; `--settings <file-or-json>` adds one settings layer above your files and the environment and below flags and the managed file; `--mcp-config <file-or-json>` now also works on the interactive launch and takes inline JSON; `--strict-mcp-config` uses only those servers. Nothing existing changes meaning, and a launch that does not use them behaves as before. A bad `--settings` or `--mcp-config` is one line and exit status 64. The hooks report's `setBy.kind` can now be `launch` (with a `flag`), for a hook switch set by `--bare` or `--settings`.
