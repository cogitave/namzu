---
'@namzu/cli': minor
---

`namzu config set` (and `/config <key> <value>`) now accepts lists and small maps as words for six settings that took only JSON: `tui.notifications` (`on`, `off`, or a comma list of `turn-settled`, `approval-required`, `idle-prompt`), `tui.workspacesPrefix` (a key such as `ctrl+g`; `ctrl+c`, `ctrl+d`, `ctrl+z` and the Tab, Enter, Backspace and Escape keys are refused), `composerTriggers.builtin` (`hypermode=suggest,max-effort=arm`, or JSON; an entry set to its default is left out of the file), `toolResultScreens` (`injection,correspondence`, `none`, or JSON for the tools a screen lets through), `telemetry.sessionExport.eventTypes` (a comma list of event types, `none`, or `all`, which removes the key) and `telemetry.sessionExport.redactors` (`on` or `off`; off asks first). Nothing already written to a config file changes meaning. `namzu config get` and `--json` now describe these with new control kinds (`toggle-checks`, `toggle-list`, `key`, `levels`, `screens`, `list`) instead of `json`; a script that read `control.kind === "json"` for these keys must handle the new kinds. A value equal to the default (every event, every trigger at its default, the default screen alone) is removed from the file instead of written.
