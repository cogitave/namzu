A click, key or text typed into a Windows window now asks the desktop driver for fewer window lists. The driver's list of windows takes over a second on a real desktop, and one input used to read it up to six times: before the send, for the check that the window had not moved, and at each of the four waits that look for the input's effect. It is now read once before the send (the same list also answers the moved-window check), and afterwards only at the first wait, at the last wait, and at any wait where the window's own contents changed. An input the driver confirms itself now costs one list instead of two; one it cannot confirm costs three instead of six. Every refusal and every outcome is unchanged: a window that moved, closed, was minimized or changed owner is still refused with the same message and nothing is sent, and the result is still `delivered_verified`, `delivered_unverified` or `not_delivered` on the same evidence. The reads of the window's contents are unchanged. One difference: a new window of the same program that opens and closes again between the checks, while the window it came from shows no change, is no longer noticed. Nothing to change in your code.
