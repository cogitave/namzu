The `monitor` tool can watch a WebSocket. Give it `ws: { url, protocols? }` instead of `command`, and each line of each text frame the server sends reaches the model as a monitor event; binary frames are counted, and a close ends the watch. Everything after the source (batching, rationing, expiry, `job kill`) is shared with command monitors.

Nothing breaks for an existing caller: `command` is now optional in the tool's input (exactly one of `command` and `ws` is required, and a call with neither or both is refused), and every other new field is optional. `BackgroundJobRegistryRef.startMonitor` is unchanged (it still takes `{ command }`); the WebSocket form is a new, separate, optional method, `BackgroundJobRegistryRef.startWebSocketMonitor({ webSocket })`, also on `bindOwner(...)`. Keeping it apart is deliberate: a host that implements `startMonitor` for commands is never handed an input it was not written for, and one without `startWebSocketMonitor` simply refuses a `ws` call with a plain message. `StartJobParams.spawn` now receives a `JobHost` argument (a `spawn` that ignores it still fits) and may return a new `JobSource` as well as a `JobProcess`; `JobProcess.child` is still a `ChildProcess`, exactly as before, while `JobSource.child` is the structural `JobChild`, which a `ChildProcess` satisfies. `Sandbox.networkPolicy` is a new optional property.

A WebSocket monitor connects from the host, outside any sandbox, so it is guarded: it is refused unless the turn has web access (`ToolContext.web.fetch`), the host name resolves only to public addresses (all answers are checked and the socket is then pinned to them), and a sandbox that blocks the network lists the host in `networkPolicy.allowedHosts`. It always needs a person's approval (`requiresApproval`), in every mode, and a permission rule written for commands cannot allow it. A host that mounts the tool and wants WebSocket monitors available must give the turn a web capability; one that does not gets a plain refusal.

`ws@8.21.3` is a new runtime dependency of `@namzu/sdk`, loaded only when the first WebSocket monitor starts. `createMonitorTool(options)` and `MonitorToolOptions` are exported for tests that need a server on the local machine.

`web_fetch` shares the address check and now refuses more: a host that resolves to `100.64.0.0/10` (shared address space, which some clouds use for internal services), `198.18.0.0/15`, `192.0.0.0/24`, IPv4-compatible `::/96`, site-local `fec0::/10`, or to a NAT64 (`64:ff9b::/96`), 6to4 (`2002::/16`) or IPv4-translated address whose embedded IPv4 is private, is refused as an address inside the host. A fetch to a server reached only through one of those ranges needs `allowPrivateAddresses` on `GuardedFetchConfig`.
