Add the `bypass` and `classify` review modes, a classifier model behind `classify`, and shell file commands in `accept-edits`. `auto` keeps exactly its old meaning, so a headless host changes nothing.

- `createReviewPolicy({ mode: 'bypass' })` runs everything except what only a person may answer: a rule or hook that asked for a person (`authorization.askRule`), a catastrophic `rm`, a tool's own `requiresApproval`, a sandbox escape and a call whose safety checks threw. A `deny` rule and the dangerous-pattern floor still refuse before the policy runs. Paths outside the roots, program names nobody can read and protected writes, which `auto` still asks about, are approved. With no `prompt`, whatever would have been asked is refused with its own text.
- `createReviewPolicy({ mode: 'classify', classifier })` sends the calls `prompt` would ask about to `createAutoReviewClassifier({ provider, model, rules? })`, a two-pass model reviewer (64 then 8192 output tokens) that fails closed on any error, retries at most twice with a 2 to 10 second backoff, reads the person's messages, the agent's prose and each tool call as the tool describes it (`ToolDefinition.classifierInput`, new, defaults to compact JSON), and never reads tool results. Reads, trusted read-only tools, edits inside the roots, the safe-tool list and calls a narrow rule allowed are never sent; an allow rule for a whole shell tool, an interpreter or launcher, or a delegation tool is not honoured in this mode. Operators extend the rules with `{ allow, softDeny, hardDeny, environment }` and `"$defaults"`. Three blocks in a row, or twenty in all, are reported through `onClassifierLimit`; the SDK never switches the mode itself, and an unattended turn ends with the reason. A host using `classify` must answer `reviewAllowedCalls` with `modeReviewsAllowedCalls(mode)` and pass the second argument of its `ResumeHandler` (new, `ResumeContext`, holding the transcript) on if it wraps the policy.
- `accept-edits` also approves a shell line made only of `mkdir`, `touch`, `rm`, `rmdir`, `mv`, `cp` and `sed` when every path it names is inside the roots, if the host passes `roots`. A catastrophic removal, a protected path, a path in a variable and a `sed` script that can run a program still ask. Hosts that do not pass `roots` see no change.
- A literal `cd <relative-directory>` inside the roots is now followed, so `cd packages/sdk && echo x > out.txt` is no longer reported as writing outside them. A `cd` to anywhere else keeps the old behaviour.
- A safety check that throws no longer ends the turn or reads as clean: the call carries `escalation.unfinishedCheck` and is asked about in every mode, or refused when nobody can be asked.

`ReviewMode` gains two members. A host that switches over it exhaustively, or keys a `Record<ReviewMode, …>` by it, needs two more cases (`'bypass'` and `'classify'`) to compile; nothing at run time changes for a mode it does not use.
