'@namzu/cli': minor

New command `namzu plugin validate [path] [--json]` checks a plugin folder (the current one by default) and every part it carries: the manifest, skills, tool and hook modules, MCP server entries, command files and agent files. It prints each problem with the file, the line when it can be known, what is wrong and what the loader would do about it, as an error (the loader refuses the plugin or skips the part) or a warning (it loads but is probably not what you meant: an ignored misspelt key, a very long skill description, a reference outside the folder, a hook event that does not exist). It runs nothing from the plugin and reads only inside the folder. Exit status: 0 no problems, 10 warnings only, 1 errors, 66 folder unreadable, 64 usage. `--json` prints one report (`version: 1`) and nothing else on standard output. Nothing changes for a plugin that already loads; a script that wants to gate on it should treat 10 as "loads, check it". When a plugin is refused at startup, or a plugin's command folder, agent file or whole plugin is skipped, the message now ends with a line naming this command, and so does the reason shown for a plugin command that cannot be used. The "could not read the folder" sentence goes to standard error.
