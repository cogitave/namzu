The terminal now installs a newer Namzu in the background by default. About ten seconds after it starts, and every thirty minutes while it stays open, it looks for a newer version; where Namzu owns the install (an npm or pnpm global install in a folder it can write to, including the installer's `~/.namzu` folder) it installs the new version without asking and says once, in the footer, `Updated to X, restart to use it`. The window you are in keeps running the version it started with. Before this release the terminal only told you a newer version existed. A source checkout, `npx` and the copy inside the Desktop app are never touched, and CI does not install unless you ask.

To keep the old behaviour (a footer line that tells you, no install), set `updates: { auto: false }` in `~/.namzu/config.yaml` or `NAMZU_AUTO_UPDATE=0`. To stop looking altogether, set `updates: { check: false }` or `NAMZU_UPDATE_CHECK=0`. To follow the slower `stable` tag, set `updates: { channel: stable }` or `NAMZU_UPDATE_CHANNEL=stable`. A project config file can only turn these off, never on.

An update downloads the release itself and installs only a file whose sha512 matches the registry's digest (for npm a registry setting on your machine cannot change what is installed; for pnpm that holds for the file installed first, and the follow-up step that records the registry version pins the `@namzu` scope but resolves through the registry's listing; a version the registry gave no checksum for is refused); takes a lock kept inside each install (so windows and users with different Namzu homes never change the same install at once); runs the package's own install steps in a process of its own that writes to a log file, so closing the terminal does not interrupt it; repairs an update that was interrupted on the next start; keeps the replaced version under `~/.namzu/updates/previous`; starts the new copy and has it load what a terminal session needs (`namzu --start-check`), and puts the old version back if anything fails. A version that failed is remembered and not tried again until a newer one is published (an interrupted download is retried after six hours), and the footer says `Couldn't update Namzu on its own` only once per version. `namzu upgrade` uses the same steps, follows the configured channel, also updates pnpm global installs (leaving a registry version in pnpm's global manifest, so `pnpm update --global` keeps working, and putting the previous version back if that step fails) (including the older pnpm layouts), says when another update is already running, and `namzu upgrade --check` reports the last failed attempt and where its log is.
