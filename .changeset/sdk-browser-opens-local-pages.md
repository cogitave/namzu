The `browser` tool opens a page the agent wrote, by its path: relative, absolute, a Windows form (`C:\site\index.html`) or a `file:` URL, when the file is inside the session's work folder, a folder added to it or Namzu's scratch folder. Before, every such address was refused and an agent that built a page could not look at it. The page is served from a read-only server on 127.0.0.1 (random port, random token, one folder, no directory listing) that stops with the browser session, so relative CSS, images and scripts load and screenshots work, while nothing else on the disk is reachable. A path outside those folders, a link that leaves them, `.git`, a secret file, anything the read rules deny, and a missing file are refused with the reason. Web addresses are checked as before, and the browser is still never given a `file:` address. A host that builds the tools with `createBrowserTools` gets this without a change; call the new `closeBrowserLocalPages(host)` when the browser session ends to stop the server at once. `createBrowserTools(host, { localPages: false })` turns this off for a browser that is not on this machine; the Pal computer's browser does.
