Slash commands now work while a reply is being written, instead of being answered with "wait for the reply to finish". Commands that only show something or change a setting (`/model`, `/effort`, `/status`, `/cost`, `/tasks`, `/permissions`, `/hooks`, `/theme`, `/help` and the others listed in the slash-commands page) run at once and the reply keeps streaming; `/model` and `/effort` open as a chooser beside the stream, and Esc or Ctrl+C close only that chooser. Every other command, saved prompt command and skill is queued exactly as typed, shown under the reply as `/name · after this reply`, and runs as its own step when the reply ends, in order and ahead of messages queued behind it. A model picked mid-reply is used from the next request when the current provider serves it and otherwise when the reply ends (after a refusal handed the reply to another model, a pick is held until the reply ends and then wins; a pick made before the refusal is dropped, because that model declined); queued messages run on the new model. An effort or hypermode change applies from your next message. Behaviour change to know about: a command that used to run immediately mid-reply and act on the conversation (for example `/context`, `/compact`, `/plan`, `/review`) now waits for the reply to end. `/clear`, `/new`, `/fork`, `/resume` and `/copy` also wait for the reply to end instead of running at once; a `/clear` or `/new` typed mid-reply no longer stops that reply, and messages queued behind it are kept for the new conversation. Nothing is removed; to run one right away, press Esc to stop the reply first.
