A plugin can ship hook entries, and a plugin written for the common hook contract moves as written. Put them in `hooks/hooks.json` in the plugin folder (read when it exists), in a `.json` path listed in the manifest's `hooks` (any other path in `hooks` is still a JavaScript module), or inline under the new manifest key `hookEntries`, as the events object itself or under a `hooks` key, in either shape. They are read by the same reader a config file's `hooks` key goes through, so problems are said the same way and one bad entry never stops the others; a path that leaves the plugin folder is refused. A command is started with `NAMZU_PLUGIN_ROOT` (the plugin's folder) and `NAMZU_PLUGIN_DATA` (a folder kept for the plugin under the Namzu home, created when first needed, never inside the plugin), and `${NAMZU_PLUGIN_ROOT}` and `${NAMZU_PLUGIN_DATA}` are replaced in the command and arguments; a variable of another tool that ends in `_PLUGIN_ROOT` or `_PLUGIN_DATA` is given the same folders.

The entries live while the plugin is on: enabling a plugin (`/plugins`, its saved state, `--plugin-dir`) attaches them and disabling it removes them at once. `/hooks` lists them apart from the plugin's JavaScript hooks with the plugin's name, event, command and matcher, `/plugins` shows how many a plugin ships, `namzu doctor` counts them and reports their problems, and `namzu plugin validate` checks every file and names each problem (`hook-entries-*`). `disableHooks` and `NAMZU_DISABLE_HOOKS` turn them off, and so does `hooksManagedOnly` (no plugin comes from the managed file); the plugin's JavaScript hooks are not touched by any switch. A project plugin is read only after the folder is trusted, and the terminal's trust prompt lists the entries a project's plugins would run, with the plugin's name, before the answer. The Desktop app's trust dialog does not read plugin folders yet.

One change to check: a command in a config file that refers to a variable ending in `_PLUGIN_ROOT` or `_PLUGIN_DATA` (which only a plugin's own entries are given) is now reported as a problem and not started with an empty path; a guard with `onFailure: block` refuses instead of passing. To keep such a command, give the variable a value with the entry's `env` or export it.
