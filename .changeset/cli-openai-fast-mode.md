Fast mode now works on OpenAI models, so a saved `fast: true` now also takes effect on OpenAI models that offer fast mode (an API key on a listed model, or a Codex subscription model whose account lists a fast tier), where it used to be reported as not applied. That costs more on an API key (a multiple of the standard rate, 2.5 times on `gpt-5.5`) and uses more of your plan allowance on a subscription. To keep the old behaviour, remove `fast` from your config file or set it to `false`; `--fast` and `/fast` still start from off. Applying it at launch now says what it costs in one line. New: `/ultrafast` asks for the faster tier on the Codex subscription models whose account lists it, for that conversation only (it is never saved and has no launch flag; `--fast` stays a flag with no value); the footer shows `ultrafast`; `/fast` with no argument turns fast mode on, off when it is on, and switches ultrafast to fast, and `/ultrafast` does the same for its tier; the usage lines are `/fast [on|off]` and `/ultrafast [on|off]`. Each command shows in the command menu only on a model that offers the tier (typed anyway, it answers with the reason, and `/help` lists both). A model change keeps the mode only when the new model offers the tier on now, and otherwise turns it off with the reason. Any other provider is still refused, now with "Fast mode is available on Anthropic and OpenAI models only."
