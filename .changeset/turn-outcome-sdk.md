A turn now has a record of what it changed and what checked it, built from its own tool calls and never from the model's answer: `Turn.outcome` and `BaseAgentResult.outcome` (type `TurnOutcome`, verdicts `unchanged`, `checked`, `stale`, `failing`, `inconclusive`, `unchecked`, `unknown`). `checked` means a recognised check passed and the workspace did not change after it; it does not mean the check covers the change, and a check run through a pipe, `;`, `||` or `&` is `masked` and never counts as passed. The record is stored in three new record types of the session log, `turn_outcome_recorded` (just before a turn's end record), `child_outcome_recorded` (in the parent's log, just before `child_session_ended`) and `outcome_progress_written` (just before a checkpoint's record, so a resume restores it), each flagged `ignorable`; it is also on the workflow journal's `agent_outcome`. No existing record or checkpoint gains a field, and earlier versions skip the new record types, so an earlier version reading a log this version wrote loses only the outcome and reads everything else. A turn resumed with no progress record reports no outcome. Read it back with `readTurnOutcome`, `foldTurnOutcomes` and `foldChildOutcomes`. `TurnConfig.outcome` takes `detectChanges` (a workspace fingerprint, `fingerprintWorkspace` is one), `isCheck` and `detectTimeoutMs` so shell-made changes are seen. The `Agent` tool's `data.outcome` carries a child's record and one kernel-written line follows the child's marked block (`describeOutcomeRecord`, `KERNEL_RECORD_PREFIX`); `untrustedEnvelopeBody` skips one trailing line of that kind. `ToolCallOutcome.facts` is the typed result of a call. A host that only reads `Turn` and `BaseAgentResult` is otherwise unaffected.
