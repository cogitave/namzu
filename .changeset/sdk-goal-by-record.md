New, optional: a goal can end by the kernel's record of the work instead of the model's report. `SessionGoal` and `CreateSessionGoalParams` gain `confirmedBy?: 'model' | 'record'`; `GoalConfirmation` (with `decideGoalConfirmation`, `recordSentence`, `describeGoalEnding`, `DEFAULT_GOAL_REFUSALS` and `NO_CHECK_REASON_CODE`) holds a `complete` report until the answer is finished and decides from the turn's outcome record: confirmed, stated and not checked, or not confirmed, refusing with one plain note up to 3 times. Pass it to `buildSessionGoalTools(store, resolve, { confirmation })` and give each goal round `TurnConfig.outcome.beforeEnd = confirmation.beforeEnd(turnId)`. `beforeEnd` is a new general hook: it is asked when a turn would end, may return a note that sends the model back (16 at most per turn, limits always win) and reads the record through `read()`. `/goal set` accepts `--confirmed-by record|model`. Nothing changes unless you pass these: without `confirmation` the goal tools are exactly as before. One fix that applies to every host: the goal tools `get_goal` and `update_goal` no longer count as calls that might change files, so reporting a goal complete after a passing check no longer makes that check read as not known to be fresh (verdict `inconclusive`).
