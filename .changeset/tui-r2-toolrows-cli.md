Tool rows in the terminal read the way the rest of the product does. An edit or a write shows the change as hunks (a line-number gutter, three lines of context, `...` between hunks) under a headline with the right counts (`Edited a.ts +2 -1`), also for batch edits, insertions and `replace_all`; a created file shows its first 10 lines. Every folded body ends in `… +N lines (ctrl+o to expand)` (with `(~N KB)` from 1,000 hidden characters) instead of three different phrasings; settled tool rows use `●` and `⎿`, and a step under a second shows no duration. A tool error names the file relative to the working folder (or `~/x`, or the full path) instead of a raw absolute path or `../../x`, and long paths wrap at a separator. Previews no longer cut through an emoji. The Desktop transcript reads the same counts from the kernel instead of recomputing them. `/diff` groups the patch per file under a plain header with its counts and draws the hunks the same way. The undo status the Desktop reads (`namzu/turns/undo-status`) now calls the number of files a reply created and deleted `created` and `deleted` instead of `added` and `removed`, which read as line counts; only the Desktop reads them, and it accepts both names.
