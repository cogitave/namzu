Namzu now learns from the failures and recoveries your conversations keep, by itself, in the background of the interactive terminal. It is on by default; set `learningGenerator: false` in your user config to turn it off. When at least 5 new observations have accumulated, 6 hours have passed since the last cycle and the daily token allowance is not used up, one cycle proposes a revision of the folder's guidance, checks it against fixed scenarios (blind grading, tasks that must not regress, a fresh confirmation round) and activates it only for the exact revision that passed; most cycles end rejected, which is the gate working. Each cycle stops at 120,000 recorded tokens and all cycles at 300,000 per day (`learningGenerator: { cycleTokens, dailyTokens }` changes them; a project file can only lower them). It uses the configured `smallModel`, else the cheapest text model of the active provider. `exec`, scheduled runs and sub-agents never start it. `namzu learn` with no module runs one cycle now, `namzu learn --list` shows what was learned and `namzu learn --undo` restores the guidance an activation replaced. Passing a module to `namzu learn` works as before. If you do not want conversations to spend tokens on this, set `learningGenerator: false`; setting `learningObservations: false` also stops it because nothing is kept to learn from.
