'@namzu/sdk': minor

A plugin folder written in the common plugin layout now loads without a `plugin.json`. `loadPluginManifest` falls back to a new reader (`readCommonLayout`) when there is no `plugin.json`: it reads the layout's own manifest, a root `SKILL.md`, or just the conventional folders, auto-scans `skills/`, `commands/` and `agents/`, takes a command or agent as a single file, reads a root servers file in its keyed and flat forms, and reports every entry as used, ignored, not used or refused (`loadPluginManifestWithFindings`, `PluginLifecycleManager.layoutFindings`). `discoverPlugins` now also finds a folder whose manifest is the layout's. `install` takes an optional `manifestSource` for a manifest the caller already read. Plugin manifests may list `remoteMcpServers`, which are parsed and reported and never started, and the per-plugin caps rise additively: skills 20 to 64, MCP servers 5 to 16, command and agent entries 10 to 64. Nothing existing breaks: a folder with a `plugin.json` is read as before. One difference to know: a folder that has no `plugin.json` used to fail to load with a file error and now either loads or fails with a sentence saying why. `${NAMZU_PLUGIN_ROOT}` in a plugin skill's text is now replaced by the plugin's folder, and a hook of a plugin read through the layout also gets the three compatibility environment names (`PluginFolders.layout`).
