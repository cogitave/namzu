Hooks gain two events and can set variables for later commands. `file_changed` fires once a watched file has been still for half a second (`filePath`, `change`: `add`, `change` or `unlink`); `cwd_changed` fires when the folder the shell tool's next command starts in changes (`oldCwd`, `newCwd`). Both are in `PluginHookEvent` and `SHELL_HOOK_EVENTS` (`FileChanged`, `CwdChanged` in the common shape); a hook answers with `hookSpecificOutput.watchPaths` (the files to watch from now on) and `systemMessage`, and cannot refuse anything. A command hook on `session_start`, `cwd_changed` or `file_changed` is started with `NAMZU_ENV_FILE`; with `ShellHookOptions.hookEnv` (a `SessionHookEnv`) its `export NAME=value` lines become the environment of later shell commands. New exports: `SessionHookEnv`, `FileChangeHooks`, `FileChangeWatcher`, `fileChangedMatches`, `fileChangedMatcherPaths`, `QueryParams.onWorkingDirectoryChange`, `ToolContext.workingDirectoryChanged`. Nothing is removed or changed by default. If you switch on a union of event names (`PluginHookEvent`, `ShellHookEvent`) with an exhaustive check, add the two new names. A `file_changed` hook that writes the file it watches runs once for the change that started it, not again every half second; a matcher naming a file in a folder not yet made is watched when the folder appears. A variable two hooks of one kind both set takes the value of the one later in the configuration. `__proto__`, `SHELL`, `PYTHONPATH`, `PYTHONHOME`, `RUBYLIB` and the programs Git runs on its own (`GIT_SSH`, `GIT_SSH_COMMAND`, `GIT_ASKPASS`, `GIT_PROXY_COMMAND`, `GIT_EXEC_PATH`, `GIT_EXTERNAL_DIFF`) are refused as hook variables: set `PATH` to reach another interpreter or tool instead. `SessionHookEnv.fileFor` and `absorb` take an optional slot (the hook's place in the configuration); callers that pass none behave as before.
