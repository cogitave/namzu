A hooks module can no longer climb out of its context to the worker: `$`, `console`, the event, `next` and its signal are now made inside the module's context, so `console.log.constructor` and `e.constructor.constructor` no longer reach `process`. What a module loses: `URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `AbortController`, `atob`, `btoa` and `structuredClone` are no longer defined in it (a module that used them should do without or parse the text itself), and the scan now refuses `constructor`, `__proto__`, `getPrototypeOf` and the like with the file and line. A dispatch may take no more than six times its budget in all (60 seconds), calls on `$` included, then the worker is ended and the programs it started are killed; a cancelled hook that does not stop within a second has its worker ended. `$.process.run` starts a program with `PATH`, `HOME`, the locale and temporary folder variables and the names the module reads with `$.env.get`, no longer the whole environment; a module that needs another variable names it with `$.env.get` or passes `env` to `run`. `namzu plugin validate` says a module the scan refused is not run (`hooksModule.status` is `refused`, and `hooks[].runs` is false), says a module that registers nothing Namzu runs is not loaded (`empty`), and prints each not-used line once.
