Add the opt-in `monitor` tool: it starts a shell command as a background job and tells the model about each line the command prints to stdout while the model keeps working, for the case where `bash run_in_background` plus `wait_for_job` (one notice when the command ends) is not enough. Nothing changes for a host that does not opt in. The tool is not in `getBuiltinTools()`; mount `getMonitorTools()` (deferred if you like), and the new fields below are all optional. Lines are batched in a fixed 200 ms window, rationed by a ten-batch token bucket, and a source that stays suppressed for 30 seconds is stopped; a monitor expires after `timeout_ms` (default 5 minutes, capped at 30 minutes, or at `QueryParams.monitorTimeoutCapMs` where a host sets it lower) with one notice, and counts toward the per-owner job cap. Process output only ever reaches the model inside the untrusted envelope. New surface: `MonitorTool`, `getMonitorTools`, `BackgroundJobRegistry.onMonitorEvent` / `monitorStats`, `StartJobParams.monitor`, `BackgroundJob.kind` / `description` / `expiresAt` / `stopReason`, `describeMonitorEnd`, `createMonitorStream` and the `MONITOR_*` constants, `bindOwner(...).startMonitor`, the optional `BackgroundJobRegistryRef.startMonitor`, the `monitor_event` session event (`monitor.event` on the SSE wire; declined on A2A), `monitor` on `background_job_exited`, and `QueryParams.onMonitorEventsDelivered` / `monitorTimeoutCapMs`. A host that wakes an idle session should do so on `monitor_event` and treat it as delivered only when `onMonitorEventsDelivered` (or `onJobNoticeDelivered` for the monitor's end) says the model read it. A turn that owns its own jobs (no `backgroundJobOwner`) now stays open while it owns a running monitor, until an event or the end arrives, the monitor expires, or the turn is aborted; a session-owned monitor never holds a turn. If you switch exhaustively over `SessionEvent['type']`, add a `monitor_event` case. `monitor_event` is live only: it is not written to the session log, so do not look for it there; `background_job_exited.monitor` is the durable record. A notification over 100,000 characters drops whole events and says how many, and nothing is delivered after a monitor's expiry or stop notice. A host that holds monitor output for a later turn renders it exactly as the kernel does with `formatMonitorEvent`, `formatMonitorEnd` and `capMonitorNotifications`, and reads `backgroundTasksDisabled()` instead of the environment variable.
