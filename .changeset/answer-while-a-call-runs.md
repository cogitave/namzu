A host can now let the model answer the operator while a long tool call is still running. Set `QueryParams.answerWhileCallsRun: true` together with the new `QueryParams.waitForOperator(signal)`, which resolves when the operator wrote and for no other reason (a child's notice or a peer's mail, which wake `waitForInbound`, never hand a call back). When the operator writes during a tool batch that has run for two seconds, each unfinished call is answered with a "still running" placeholder, the model reads the message and replies at once, and the real result follows in a message that names the call id; the turn is held open for it. Nothing changes for a host that leaves it unset (the default), and a batch under per-call review is never detached. A host that turns it on must make `waitForOperator` free of side effects, because it is called during tool batches. A call queued behind an earlier one that has not begun is told it has not started, not that it is running. The coding-agent delegation doctrine, which every parent session receives, gains a short section on answering "how is it going": read the running-work note, give each item its state and age, say an unfinished item is still running, and offer to run one that died again. The section assumes the host may give the model a note about running work and reads conditionally when it does not. That changes the cached prompt prefix once.
