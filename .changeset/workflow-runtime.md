Add `WorkflowRuntime`, which runs a model-authored workflow script: a JavaScript program, written once, that decides how many subagents run and in which order (`agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`, `args`, `budget`). The script runs in the same QuickJS interpreter as `run_code`, and `agent()` is its only capability; your `spawnAgent` callback decides what starting an agent means, so it can go through the same policy and accounting as your own delegation. New exports: `WorkflowRuntime`, `parseWorkflowMeta`, `resolveWorkflowLimits`, `summarizeWorkflowPhases`, `FileWorkflowJournal`, `WorkflowScriptError` and the `Workflow*` types (events, limits, journal records, results). Nothing existing changes behaviour. `RunCodeOptions` gains two optional fields, `cpuLimits` (bound synchronous interpreter time per stretch and in total instead of the whole run's wall clock) and `onOutput` (each printed line as it is printed); a custom `CodeRuntime` may ignore both. A script that throws or does not parse fails with `error` set to the error name and message, the script line and column, that line's text, and how far the run got (agents started, finished and failed, last phase); `parallel`, `pipeline` and `agent` reject wrong argument shapes with a message naming the signature. The `failed` `CodeRunOutcome` gains optional `errorName` and `frames` (line and column in the submitted source) for a host that wants to build its own message.
