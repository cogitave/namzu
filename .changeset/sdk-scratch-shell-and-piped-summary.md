'@namzu/sdk': minor
---

A shell write into the session scratch folder through `$NAMZU_SCRATCH` (`printf x > $NAMZU_SCRATCH/out.csv`) no longer asks "Outside the working directory". A test run piped through `tail` or `grep` whose output shows the runner's own summary (node, vitest, jest, pytest, cargo, go), or that uses `set -o pipefail` or `exit ${PIPESTATUS[0]}`, is counted as read, so the end-of-turn line no longer says the pipe hides whether it passed after a passing run (a failing summary now counts as a failure). A saved shell rule covers a line whose other commands only read, and declines a line that writes a file through a redirection. New exports: `isReadOnlyCommandLine` and `writesThroughRedirection`. Behaviour change for operator rules: an `argument_pattern` allow rule on a shell command (`make *`) no longer covers a line that also writes a file through a redirection (`make > build.log`); such a line is asked about, as before the rule existed. A go test run piped through `tail` is read as passed only from a bare `PASS` line, not from `ok` lines alone, since an earlier package's `FAIL` may have been cut. `exit ${PIPESTATUS[0]}` counts as the check's own status only when the check is the first stage of its pipe.
