Settings now shows what runs by itself. **Settings > Tools** lists the hooks of the project you are in (or your own, when no project is open), grouped by when they run: what each one starts, where it comes from, where to change it, and whether it runs, is off, waits until a skill or agent is used, or could not be loaded, with the reason. A hook that could not be loaded is shown where it would have been, not in a log. The list is read-only and never shows a secret: an `env` value or a header is not in it, and a web address loses its query and credentials. A new switch, **Run hooks**, turns the hooks from your own and a project's files off and on (it is the `disableHooks` setting turned the other way round); when your administrator's file or the `NAMZU_DISABLE_HOOKS` variable decides, the switch is greyed out and one line says so.

The "Trust this folder?" dialog now lists everything a folder would start by itself before you answer: the hooks of its config files as before, and now the hook entries of its plugins and the hooks carried by its skills and agent files, each named with where it comes from. It takes this from the engine, so it needs an engine that knows the question; with an older engine the dialog reads the config file as it did and says in one line that its list may be incomplete. Nothing to do when upgrading, and nothing here starts a hook.
