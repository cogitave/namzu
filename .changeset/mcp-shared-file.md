A project's `.mcp.json` is now read as shared tool servers, in the `{ "mcpServers": { ... } }` shape, but a server from it starts only after you approve it. The folder-trust screen lists the servers the file declares, each with the command it runs or the address it reaches, and accepting it approves exactly the entries shown; for a folder you already trust, or a server added or changed later, Namzu says at start that servers are waiting, and `namzu mcp approve [name...]` starts them. An approval covers the exact entry, so a changed command or URL asks again; answers are kept in `mcp-approvals.json` in the Namzu home directory. `mcpServers` from the highest layer replaces the lower ones as a whole, so a project table hides servers in your user config. A server that `namzu.config.json` also names keeps the config entry. `namzu exec` (and `exec --json`) also takes `--mcp-config <file>`, repeatable, to add servers for one run without approval since you name the file; a missing file stops the run with a usage error. Nothing to change unless a project you trust already has a `.mcp.json`: its servers now wait for `namzu mcp approve` (in `exec`, run it once first; `exec` prints one line naming the servers that are waiting).
