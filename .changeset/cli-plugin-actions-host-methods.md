The desktop host gains methods for adding marketplaces and installing, enabling, updating and removing plugins from the Customize page, under the optional capability group `pluginsManage`: `namzu/marketplaces/preview`, `add`, `list`, `remove`, `update` and `available`; `namzu/plugins/plan`, `stage`, `install`, `enable`, `update_check`, `update` and `uninstall`; and `namzu/ops/cancel`, which stops a long step before anything is written (progress goes out as `namzu/ops/progress`). Nothing is installed on a guess: `plan` returns what the plugin runs, including hook modules and what a remote server would send, with a digest, and `install` refuses any digest but the one shown. `namzu/plugins/list` rows gain `id`, `marketplace`, `layout`, `installed`, `findings` counts and `updateKnown`. Existing callers are unaffected; an older app simply does not offer the group. The same methods take every source the command line takes: a repository, `owner/repo[#ref]`, an https marketplace address and catalog entries from `github`, `url`, `git-subdir` and `archive` sources are fetched aside with progress and a cancel that kills Git and removes the staging folder, after `plugins.blockedMarketplaces` is checked; `namzu/marketplaces/update` fetches a repository marketplace again (a commit-pinned one does not move) and `namzu/plugins/update_check` refreshes only the plugin's own marketplace. `namzu/marketplaces/preview` rows gain `description`, and `update` results gain the outcomes `up-to-date` and `pinned` and a `message`.
