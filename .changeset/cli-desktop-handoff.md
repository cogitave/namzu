A turn a tool paused for a person (a sign-in, a CAPTCHA, a second factor) can now be continued or closed from the Desktop application, as the terminal already could. The desktop retry status (`namzu/sessions/retry-status`) has a new optional `handoff` field (`turnId`, `checkpointId`, `reason`, and for the browser `tool`, `cause`, `origin`, `profile`, `loginCommand` and `window`, which says whether the agent's browser has a window) together with `closable: true`, where it used to carry only a notice. `namzu/sessions/retry` resumes a handoff from its checkpoint with a note that the person chose to continue, and `namzu/sessions/abandon-paused` closes one; before, both refused it. A client that does not read `handoff` sees a pause with no notice and no `retry`, as before. In a Desktop conversation a sign-in page that only shows a password field now tells the model to ask the person to sign in in the browser window instead of naming `namzu browser login`; the terminal and unattended runs are unchanged. Nothing to change for existing callers.
