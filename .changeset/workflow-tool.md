Add the `workflow` tool. When you ask for one (hypermode on, the word "workflow" or "iş akışı" in your message, or `/workflow <what to do>`), the model can write a short script that starts many agents in phases and runs them in the background. Before anything starts you see its name, purpose, phases, agent limits and the script (`d` shows all of it) and approve once; in `auto` mode ("bypass permissions") it starts without asking, and a session with nobody to ask refuses with a plain reason. Its agents are ordinary children under the same permission mode, rules, sandbox and budget as the `Agent` tool, but they are not subagent rows: the run is one row on the rail (`◯ name ▰▱ 3/6 · 12s · ↓ tokens`) opening to its phases (declared ones listed before they start), then a phase's agents, then an agent's transcript; `x` stops the run on the phases and skips one agent on the agents. The conversation shows `● Workflow(<purpose>)` at launch and `✓ Workflow <name> completed · …` when the run ends, `/workflows` lists this conversation's runs (earlier ones from their journals under `<session>/runs/<runId>/workflow/`), and the model gets one message with the result when a run ends. Nothing changes for conversations that never ask for a workflow. The workflow tool is offered only by hosts that can review a background run (the terminal and `namzu exec`, not the desktop app yet). A finished workflow and a background command that ends on its own now start a turn at once when the session is idle, so the model reports without you typing (a command you stopped yourself does not). `namzu exec` waits for a workflow the model started, lets the model report, and then exits. New config keys: `workflow.maxConcurrency` (1-16, default min(8, CPUs-2)) and `workflow.maxAgents` (1-1000, default 200).
