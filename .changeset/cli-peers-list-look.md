"@namzu/cli": minor
---

`/peers` and `namzu peers list` now print one counted list, `Namzu sessions (N):`, with a line per session shaped `[state]  ·  name  ·  started 7m ago` (this terminal, or the machine's name, in the last field). A session with no name of its own reads `(unnamed session)` instead of its folder's name; its folder, permission mode and role move to an indented second line, and the other machines go in a short `Machines` section. The old one-line forms (`ref  title  state  mode` in a shell, `name [ref] · state · mode` in the terminal) are gone, so a script that parses the text should read `--json`, which keeps every field and adds `folder`, `named` and `startedAt` to its rows. The model's `list_sessions` rows gain `started_at`.

The local list now shows every live Namzu session of this user on this computer, in any folder (before, only the current project's), and a listed session can be messaged by name or ref from any folder with `/peers send`, `namzu peers send` and `send_session_message`; the receiving terminal no longer refuses a terminal or command-line sender for being in another folder. A name two folders share is refused with the candidates (use the ref). Mail from another session is still held, never treated as the person, and mode, bypass and consent rules are unchanged. The folder on a printed row is the full path, `~/…` under home; `--json` keeps `folder` as the folder's name and adds `path` with the full path (the network view still gives the name only). The error text for no match reads `No matching terminal on this computer`.
