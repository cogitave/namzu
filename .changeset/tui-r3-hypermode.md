Hypermode no longer changes the reasoning effort. Before, `/hypermode on`, the effort picker's last stop and the one-turn `hypermode` keyword pinned the effort to `xhigh` (or the highest level below it), and turning the mode off put the old effort back; the picker stop was named `xhigh + hypermode (workflows)`. Now hypermode is an independent on/off: turning it on or off, with the picker's Tab key or its last row, or typing the keyword, leaves the effort as it was, and the messages say so (`Effort stays high.`). The picker row is `hypermode (workflows)` and the footer's effort item reads `effort high · Hypermode on`. A model switch no longer re-pins an effort, and the effort chooser that follows a `/model` pick now opens whether or not hypermode is on. If you relied on hypermode to raise the effort, choose the level yourself with `/effort xhigh`; nothing else is needed to keep the mode. Choosing a level while hypermode is on leaves it on.

What the model is told also changed. The `workflow` tool is now in the tool list on every turn of a terminal or `exec` run that can start one (before, it was added only on turns with hypermode on, or the `workflow` keyword), and the model is gated by wording: the tool text and a stable system-prompt note say it may be called only after an opt-in (the `hypermode` or `workflow` keyword, hypermode on, your own words, a named saved workflow). The hypermode delegation text left the system prompt; while the mode is on the model gets a short hidden reminder instead, kept in the conversation: in full on the first message, sparsely after ten of your messages, and once when the mode ends (the mode no longer changes the cached prompt, and a resumed conversation does not hear the full text again). The one-turn keyword now opts that turn into the `workflow` tool rather than into `Agent` delegation, and its tag row says so (`Hypermode · this reply: offers workflows, effort unchanged`). The tool text gains the quality patterns (adversarial verify, judge panel, loop until dry, completeness critic). Any script that parsed the old `Hypermode is on for this conversation: xhigh effort, …` messages, or that expected the tool list to differ with the mode, needs updating.

New config key `hypermode: true` (boolean, default off, file only): conversations in the terminal start with the mode on, and `namzu exec`, `exec --json` and scheduled runs tell the model it is on (a run that cannot start a workflow is told to delegate to parallel agents with `Agent`).
