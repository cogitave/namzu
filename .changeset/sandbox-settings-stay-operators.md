'@namzu/cli': minor

A repository can no longer loosen your sandbox. `namzu.config.json`, `namzu.config.local.json` and a profile declared in either may now only tighten the `sandbox` block: they can turn `enabled` on, set `allowEscape` and `allowUnattendedEscape` to `false`, add to `requireIsolation` and ask for an `ephemeral` workspace. A repository value that would loosen it (`enabled: false`, `allowEscape: true`, `allowUnattendedEscape: true`, `workspace: working-directory` over your `ephemeral`) is ignored, and `teardownTimeoutMs` in a repository file is ignored; each one that would have changed something is named once at launch with its file. Before, such a file replaced your whole `sandbox` block, so a cloned repository could let a headless run leave the sandbox. If a team relied on that, move the setting to your own `~/.namzu/config.yaml` or to the managed file; both keep full control. Your own file and the managed file also now merge per key instead of the later one replacing the whole block.
