'@namzu/cli': minor

Namzu now reads the records of installed plugins and loads them. `known_marketplaces.json`, `installed_plugins.json` (version 2) and `.install-manifests/<id>.json` under `~/.namzu/plugins/`, and the keys `enabledPlugins` and `extraKnownMarketplaces` in `~/.namzu/settings.json`, `.namzu/settings.json` and `.namzu/settings.local.json`, say what is installed and whether it is on. Installed plugins load after the hand-placed ones and before `--plugin-dir`, from their own folder under `plugins/cache/`; one whose executable files changed since it was accepted, or that cannot load, is skipped and reported and the others load. A project file's yes counts only when this computer has the plugin for that folder or for you, so a repository cannot turn a plugin on by naming it; an untrusted folder reads no project record. `namzu plugin list`, `details`, `enable` and `disable` (with `--scope`, `--cwd` and `--json`) are new. Nothing existing breaks: no install record exists until the install commands arrive, so a computer without one loads exactly what it loaded before. Two small changes to know: the folders `cache`, `marketplaces` and `data` directly under `~/.namzu/plugins/` are no longer scanned for hand-placed plugins (a plugin hand-placed in one of those names stops loading; rename its folder, and both `namzu plugin validate` and the launch now warn about it), and the trust screen lists the plugins and marketplaces a folder's settings files name.
