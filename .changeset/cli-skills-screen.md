Bare `/skills` no longer opens the "Activate a skill" picker; it opens a screen of every skill where Space moves the selected one through on, name-only, user-only and off, `/` searches, `t` sorts by listing cost, and Esc saves the change for the project (a row says `No changes`, `Updated N skills in this project` or `Couldn't save skill settings`). To activate a skill for the conversation, as the picker did, type `/<name>` or `/skills <name>`, which are unchanged along with `/skills list`, `/skills new` and `/skills save`. The change is written to the new `skills.overrides` key in `.namzu/settings.local.json`: `name-only` tells the model a skill exists without its description, `user-only` keeps it from the model and its `skill` tool while `/<name>` still runs it, and `off` is the same as naming it in `skills.disabled`. A project's `overrides` entry wins over that list, and `on` lifts a name a weaker layer disabled. Also, a stronger config layer's `skills` keys now merge with a weaker layer's instead of replacing the whole table (`overrides` merges by skill name): a project file that sets `skills.disabled` no longer resets your own `skills.builtin` or `skills.suggest`. If you relied on that reset, set the keys you want in the project file.
