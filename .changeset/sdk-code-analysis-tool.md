Add the `code_analysis` tool and the `CodeAnalysisProvider` interface it calls. Nothing changes for a host that does not opt in: the tool is not part of `getBuiltinTools()` and is registered only when a host passes a provider (`getCodeAnalysisTools(provider)`, with `QueryParams.codeAnalysis` / `ToolContext.codeAnalysis` carrying it into the turn). The tool answers cited, paged lookups over a JavaScript/TypeScript index: `index`, `find_literal`, `enclosing_function`, `function_source`, `callers_of` and `imports`. Every result says what was observed, what was inferred (a callee matched by text, not by scope) and whether coverage is complete. Every provider call takes an optional `signal`, which the tool fills from the turn's abort signal so Esc stops an index; `IndexRequest.scope` indexes part of a root, and `IndexSummary.truncated` says when a call stopped at a limit and what to do next. Hits and call sites carry `stale: 'changed' | 'deleted'` when their file no longer matches the index. Paths go through the same resolver and review route as `read`, and a sandboxed turn is refused because the index reads the host file system. To use it, construct a provider (`@namzu/analysis` ships one) and pass it as `codeAnalysis` to `query()`; mount the tool with `deferred(toolset(...))` to keep its roughly 1,000-token schema out of requests that never need it.
