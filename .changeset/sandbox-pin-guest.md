`workspace.pinGuest({ sandboxUid, podUid, guestBootId })` returns a view of a Kubernetes workspace (`exec`, `readFile`, `writeFile`, `listFiles`, `openTerminal`, `openTcpConnection`, `quiesce`) that talks only to the guest you authenticated. It never follows a replaced pod: if the workspace's identity changed it rejects with the new `KubernetesGuestPinRefusedError` before dialing, and otherwise each request goes in a new `pinned` guest-agent op that the agent checks against its own boot id before dispatching anything, so a replaced or restarted guest runs nothing and the error carries the id of the agent that answered (`freshGuestBootId`). A fenced guest you pinned rejects with `KubernetesAgentRetiringError`, which now carries `guestBootId`. An identity with a missing or empty `sandboxUid`, `podUid` or `guestBootId` throws `KubernetesPinIncompleteError`. It needs the new `pinned-guest` guest feature: against an older workspace image every call on the view rejects with reason `guest-unsupported` and sends nothing, so rebuild the image from this release to use it. Calls on the workspace itself are unchanged. `PINNED_GUEST_FEATURE` is exported alongside the new errors.
