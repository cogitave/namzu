Fix `~/.namzu/index.sqlite` becoming "database disk image is malformed" after a Namzu process was killed in the middle of an index write. The next process read the file read-only, could not roll the dead writer's journal back, took the file for "not a database" and renamed a rebuilt one over it, leaving the old journal beside the new file to be played into it. The index version is now read through a writable connection that recovers the journal, only SQLite's corrupt or not-a-database answer starts a rebuild, and a rebuild takes the old file's lock before replacing it. A session that is open while another process replaces the index file now reopens it once instead of failing every later write with "attempt to write a readonly database", and concurrent rebuilders no longer replace each other's finished file. If another process keeps the index locked for about ten seconds, opening it now throws a `SessionIndexError` ("in use by another process") instead of silently renaming over the file. Nothing to change for callers.
