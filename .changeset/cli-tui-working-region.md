The area under the conversation while a reply runs is truthful and keeps its shape. The working line has a small mark of its own before the word (a disc that shrinks and swells; still under reduced motion, `NO_COLOR` and with a screen reader), the word says the phase where Namzu knows it (`Thinking`, `Writing`, `Running a command`, `Waiting for your approval`, `Retrying`, `Compacting conversation…`, otherwise `Working`), and the elapsed time is there from the second second and stays, so nothing appears later. When nothing has arrived for ten seconds the line says so and for how long (`no reply for 22s`, `Waiting for the model`) instead of only turning red, and it does not blame the network while the model is thinking or a tool is running. Your plan is one checklist under the working line that updates in place; the transcript no longer gets a block for every update, and the list as it ended is printed once when the turn finishes if it changed. While a planning call runs the line says `Updating the plan` and no longer shows the raw call. A running shell command has one dim footer line from the start (elapsed time, the time limit when the call set one, lines printed and how many are above the rows shown, and the background hint on the same line), so the box no longer moves down when the hint appears. There is no setting for any of this and nothing to change in your configuration; a script that reads the screen for `Working (…)` should look for the phase word instead.
