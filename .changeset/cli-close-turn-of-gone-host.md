A conversation no longer refuses every message after the app was closed or killed in the first instant of a reply. When a host went away after writing only a reply's start and your message, the next host treated that reply as still running and the Desktop answered "Namzu is still finishing the last reply. Give it a moment." to everything you sent. The host now closes a reply that has no host running it, with one record and your message kept, when it is asked whether the conversation can go on, and a message sent to a host that never asked closes it as well. When the host was killed and never gave its writer lease back, the reply is closed at once, but only when its lease says it was written in the same place as the host asking (the same machine host name and process-id namespace) and no process has that process id. Two things still wait for the lease's five minutes, as before: a reply whose lease was written by an older version (it names no place), and a reply held by a host in another place, such as a container or a second system that shares the same home folder, where a process id says nothing about whether that host is alive. A reply another host still runs, and a paused one, are left alone. The terminal's "in use by another window" sentence no longer takes a process of another place for itself.
